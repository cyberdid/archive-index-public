# archive-index

**Локальний пошук по всьому, що я роблю на комп'ютері.** Вікі й документація проєктів, PDF, Word, PowerPoint,
таблиці, git-історія, сесії з Claude Code і Codex, журнали запусків, зображення, аудіо з розшифровками і відео.
Один запит шукає і за словами (з морфологією української й російської), і за змістом (EmbeddingGemma 2).

Усе працює локально: модель на GPU, дані не виходять за межі машини, під час пошуку немає мережевих запитів.

Є три способи користуватися:

- **`archive-tui`** — термінальний інтерфейс: пошук, перегляд, відкриття файлів на місці збігу і граф результатів;
- **`archive`** — командний рядок для пошуку, статистики й індексації;
- **MCP-сервер** — інструменти `archive_search` і `archive_stats` для агентів (Claude Code тощо).

## Швидкий старт

```bash
VENV="$HOME/.local/share/embeddinggemma2/venv"
uv pip install --python $VENV/bin/python -e ~/Projects/llm/archive-index

# команди в PATH (~/.local/bin є в PATH за замовчуванням)
ln -sf $VENV/bin/archive $VENV/bin/archive-tui ~/.local/bin/

archive stats                    # скільки документів і фрагментів у кожній колекції
archive index                    # перший повний прогін (може тривати довго)
archive-tui                      # інтерфейс
```

Модель EmbeddingGemma 2 завантажується з Hugging Face при першому використанні (потрібен інтернет один раз).
Якщо пишеться `command not found`, перевір `echo $PATH` або запускай повним шляхом `$VENV/bin/archive-tui`.
Кнопка `i` в інтерфейсі запускає індексацію тим самим Python, тож для неї PATH не потрібен.

## Що індексується

| Колекція | Джерело | Одиниця індексу |
|---|---|---|
| `wiki` | `*.md` у `~/Projects` | розділ документа, далі по абзацах |
| `docs` | `pdf`, `docx`, `pptx`, `epub`; старі `doc`, `ppt`, `rtf`, `odt`, `odp` (через LibreOffice); `html`, `htm`; `txt` до 2 МБ; `ipynb` без виводів | сторінка, слайд, розділ або блок |
| `tables` | `xlsx`, `xlsm`, `xls`, `ods`, `csv`, `tsv` до 50 МБ | вікно 30 рядків (до 1200 символів); у кожному вікні повторюються заголовки |
| `git` | історія комітів (до 500 останніх) | коміт |
| `sessions` | сесії Claude Code і Codex | хід розмови: питання і відповідь (без «thinking» і виводів інструментів) |
| `run_logs` | `.antigravity_runs/*.jsonl` | подія: помилка, підзадача, перепланування |
| `images` | `png`, `jpg`, `jpeg`, `webp` до 15 МБ | зображення (сторінки PDF без тексту теж сюди) |
| `audio` | `wav`, `mp3`, `opus`, `ogg`, `flac`, `m4a` до 300 МБ | вікно 20 с з кроком 15 с; з розшифровками, якщо вони є |
| `video` | `mp4`, `mkv`, `mov`, `webm`, `avi` до 2 ГБ | кадр кожні 5 с і звукова доріжка вікнами по 20 с |
| `code` *(вимкнено)* | `py`, `c`, `h`, `cpp`, `ts`, `js`, `rs`, `go`, `sh`, а також README і `docs/*.md` | функція або клас (Python), блок між порожніми рядками (інші мови) |
| `config` *(вимкнено)* | `yaml`, `yml`, `toml`, `ini`, `json`, `xml` до 256 КБ | файл |
| `logs` *(вимкнено)* | `*.log` до 2 МБ | файл |

Колекції `config`, `logs` і `code` вмикаються явно, наприклад: `archive index -c code --project llm`.

**Що відсіюється.**
- **Чутливі файли** ніколи не індексуються: `*.pem`, `*.key`, `*.p12`, `id_rsa*`, `.env*`, `*secret*`, `*password*`,
  `*token*`, `credentials*`, теки `.ssh`, `.gnupg`, `.aws`.
- **Вендорні й згенеровані теки:** `node_modules`, `venv`, `site-packages`, `build`, `dist`, `output`, `tmp`.
- **Сторонні копії документації:** дзеркала сайтів, результати Doxygen, Sphinx, pdoc і javadoc, `htmlcov`, `_build`,
  `site`, службові теки Wine (`wineprefix*`). Правила діють лише на папки всередині кореня, який сканується.
- **Машинний вивід:** текст, де більше половини рядків — числа або hex, і файли з нульовими байтами.
- **Короткі уривки:** фрагменти документів і вікі з менш ніж 20 буквами (номери сторінок, розділові знаки),
  якщо в документі є довші. Документ, що складається лише з короткого тексту, лишається.
- **Числові таблиці** (понад 60 % цифр і знаків) індексуються лише за словами, без векторів.

## Як шукається

Кожен фрагмент має два подання.

- **Слова (FTS5, BM25).** Текст розбивається на слова й леми: українською й російською через `pymorphy3`.
  Запит «точку доступу» знайде «точка доступу». Ідентифікатори (`36.101`, `19.6.0`, `RVZ0014A`) шукаються
  як точна фраза, без розбивання на частини.
- **Зміст (EmbeddingGemma 2).** Документи кодуються з префіксом `title: … | text: …`. Запити йдуть з промптом
  `SearchQuery`, а для колекції `code` — з промптом `CodeRetrieval`. Тексти, зображення і аудіо живуть в одному
  векторному просторі.

### Режими

| Режим | Що робить | Коли |
|---|---|---|
| **hybrid** (за замовчуванням) | обидва пошуки, порядок визначає адаптивне злиття | більшість запитів |
| **lexical** | лише слова | точні слова, ідентифікатори; швидко, без GPU |
| **semantic** | лише зміст; завжди повертає top-k | описові запити |

### Адаптивне злиття

1. Беремо найкращий збіг за словами і рахуємо, яка частка слів запиту є в його тексті.
2. Якщо частка ≥ 0,9, це точна фраза: показуються лише збіги за словами, без семантичного доповнення.
3. Якщо слів немає взагалі, семантичні результати *не* підставляються автоматично. У TUI з'являється пояснення
   і підказка натиснути `s`, щоб побачити результати за змістом.
4. Інакше спершу семантичні, потім лексичні.

Серед точних збігів першими ідуть фрагменти, де слова запиту стоять у тому самому порядку і поруч. Це важливо
для числових рядків CSV та XLSX, де BM25 не розрізняє рядки.

### Ідентифікатори

Запит `36.101 антена` означає: `("36.101") AND ("антен" OR "антена" OR …)`. Ідентифікатор обов'язковий, а слова
звужують результат.

### Формат

Фільтр формату (клавіша `e` у TUI) діє на кандидатів пошуку, а не на вже відсортований top-k, тож рідкісний
формат не зникає з результатів.

### Колонка «схожість»

Косинус між запитом і фрагментом, тільки для збігів за змістом. Збіги лише за словами її не мають (показується `-`).
Поріг мін. схожості (поле в інтерфейсі) діє лише на збіги за змістом.

## Термінальний інтерфейс

```
archive-tui
```

Угорі поля запиту, проєкту, мін. схожості і ліміту. Таблиця результатів: тип збігу, колекція, проєкт, назва,
місце, схожість. Праворуч — деталі обраного фрагмента з підсвіченими словами запиту.

| Клавіша | Дія |
|---|---|
| `/` | фокус у поле пошуку (сам символ `/` у полі не друкується) |
| `Enter` у полі запиту | пошук |
| `↑` `↓` | перехід між результатами; деталі оновлюються |
| `Enter` або `→` на рядку | розгорнути документ: усі його фрагменти в деталях |
| `Esc` | фокус на результатах (з поля запиту) |
| `p` | поле проєкту (префікс назви проєкту) |
| `m` | режим: hybrid → lexical → semantic |
| `f` | колекція: all → wiki → docs → … |
| `e` | формат: все → pdf → docx → … → audio |
| `s` | семантичні результати для запиту без збігів за словами |
| `o` | відкрити файл на місці збігу (див. нижче) |
| `g` | граф результатів у терміналі (див. нижче) |
| `b` | граф у браузері (HTML-файл) |
| `i` | індексація у фоні |
| `Ctrl+Q` | вихід |

**Відкриття на місці збігу** (`o`):
- **аудіо** — `mpv --start=N` з секунди збігу (запасний варіант `gst-play-1.0 -a -s N`; якщо немає жодного,
  відкривається вирізаний фрагмент);
- **відео** — з секунди кадру або звукового вікна;
- **PDF** — на сторінці (`evince --page-index`);
- **код** — на рядку (`code -g файл:рядок`);
- інші файли — системним обробником (`xdg-open`).

**Журнал.** Усі дії й помилки пишуться в `~/.local/state/archive-index/archive.log`: кожен пошук із параметрами,
час, кількість результатів, відкриття файлів, необроблені винятки з повним traceback. Журнал не містить
тексту фрагментів, лише запити, шляхи й числа.

## Граф результатів

Показує результати, які зараз на екрані, як карту зв'язків.

**У терміналі (`g`).** Екран з текстовим графом:
- запит, кількість фрагментів і близьких пар;
- **групи близьких за змістом**: фрагменти, пов'язані між собою через близькість векторів, з колекціями
  і найкращими представниками;
- **фрагменти за схожістю**: номер, колекція кольором, шкала `████░░`, косинус, назва і місце, а також
  найближчі сусіди (`↔ #3(0.91)`).

`↑` `↓` — прокрутка, `Esc` або `q` — закрити.

**У браузері (`b`).** Інтерактивна картинка: запит — яскравий нейрон у центрі, фрагменти — нейрони з гілчастими
дендритами (довжина залежить від схожості), кольори за колекціями, світні зв'язки для близьких пар.
Файл записується в `~/.local/share/archive-index/graphs/`. Браузер можна задати змінною `ARCHIVE_BROWSER`
(наприклад, `google-chrome`); якщо її немає, використовується системний обробник HTML.

Картинку можна згенерувати й з командного рядка:

```bash
PYTHONPATH=src python tools/visualize_search.py "твій запит" -k 60 --out viz/запит.html
```

## Командний рядок

```bash
archive search "точку доступу" --mode lexical
archive search "як ми налаштовували Jetson" -c sessions -k 5
archive search "реверс" --project demo-radio --json
archive search "36.101" --per-document 0          # без групування по документу
archive stats                                     # документи і фрагменти по колекціях
archive index                                     # повний інкрементальний прогін
archive index -c sessions                         # тільки сесії
archive index -c code --project llm               # код одного проєкту
archive index --force -c docs                     # перечитати всі документи колекції
archive index --skip-screenshots                  # не індексувати скріншоти
archive rebuild-terms                             # перерахувати слова (після зміни правил морфології)
```

**`archive search`:**

| Опція | За замовчуванням | Значення |
|---|---|---|
| `-c`, `--collection` | всі | колекцію можна повторити |
| `--project` | — | префікс назви проєкту |
| `-k`, `--limit` | 8 | скільки результатів показати |
| `--per-document` | 3 | максимум фрагментів з одного документа; `0` вимикає групування |
| `--mode` | `hybrid` | `hybrid`, `lexical` або `semantic` |
| `--grouped` | — | top-k окремо для кожної колекції |
| `--json` | — | вивід у JSON |

**`archive index`:** `-c` (колекцію можна повторити), `--projects-root`, `--home`, `--session-limit N` (для пробних
прогонів), `--force`, `--project` (для колекції `code`), `--skip-screenshots`.

Один прогін одночасно: паралельний запуск отримує повідомлення «another run is in progress» і завершується.

## Індексація й автоматичні оновлення

Більшість оновлюється сама:

- **Хук `SessionEnd`** у `~/.claude/settings.json` запускає `archive index -c sessions` одразу після виходу з сесії
  Claude Code; запис з'являється за кілька секунд.
- **Таймер `archive-index-sessions`** (systemd user) — кожну хвилину, запасний варіант для сесій.
- **Таймер `archive-index`** (systemd user) — щогодини, повний прогін усіх колекцій.
- Журнал кожного прогону: `~/.local/share/archive-index/runs.jsonl`.

**Інкрементальність:**
- файл, що не змінився (розмір і час), пропускається;
- файл, у якого змінився вміст (`sha256`), перечитується;
- сесія, що виросла, читається з останньої точки: останній хід перечитується, його старі фрагменти видаляються,
  нові дописуються; неповний останній рядок (його ще пише модель) не зчитується;
- великий PDF (понад 30 сторінок) індексується порціями по 30 сторінок за прогін; повторний прогін не дублює
  вже проіндексовані сторінки;
- вектори фрагментів з незміненим текстом беруться з бази (кеш за `body_sha`), модель їх не рахує повторно.

**Блокування й база.** Одночасно працює один прогін (`fcntl`-замок). База SQLite працює в режимі WAL з тайм-аутом
60 секунд, тож інтерфейс, таймери й прогін не блокують одне одного.

## Аудіо з розшифровками

Якщо поруч із записом лежить розшифровка (`*_transcript.txt`), текст реплік, що перетинаються з 20-секундним
вікном, додається до цього вікна, і його можна знайти словами. Суфікси варіантів запису (`_enhanced`,
`_conservative`) враховуються. Для сирих записів у `recordings/` розшифровки шукаються в `processed_recordings/`.

Попередня локальна перевірка на записах (29 записів, 56 реплік, окрема тека `audio-eval`):
- текст→аудіо за векторами: правильний запис першим у 50 % реплік (випадковий вибір дає 3,4 %);
- пошук словами (три випадкові слова з репліки) знаходить правильний запис у 100 %. Це верхня межа: слова взято з
  того самого тексту, тож на реальних запитах результат буде нижчим через помилки розпізнавача.

## Безпека даних

- Перед записом у базу текст проходить редагування секретів (`redact.py`): ключі OpenAI, AWS, GitHub, Slack,
  Bearer-токени, блоки приватних ключів, пари `api_key=…` і `password: …`. У базі лишаються назви типів, а значення
  не зберігаються.
- Файли бази, журналів і графа створюються з правами `0600`.
- Thinking-блоки і виводи інструментів у сесіях не індексуються.
- Журнал не містить тексту фрагментів.
- Модель локальна; під час пошуку немає мережевих запитів.

## Оцінка якості

Скрипти в `tools/`:

| Скрипт | Що робить |
|---|---|
| `build_eval.py` | будує набір запитів з індексу: 6 точних на кожен з 11 форматів, 8 без відповіді, 6 описових; джерело і мова кожного запиту |
| `score.py` | прогін набору: Hit@1/3/5, MRR@10 по форматах, звіт у `evals/reports/`, список промахів, порівняння з попереднім звітом (`--baseline`) |
| `reference_check.py` | 30 еталонних векторів (20 текстів, 5 зображень, 5 аудіо) у `evals/reference.npz`; перевірка косинуса ≥ 0,999 |
| `llama_reference_check.py` | перевірка llama-server проти еталону |
| `negative_real.py` | випадкові слова, яких немає у файлах, мають дати нуль збігів і в архіві, і в `grep` |
| `eval_archive.py`, `final_holdout.py`, `tune_weights.py` | ранні набори й підбір ваги лексичного шару |
| `visualize_search.py` | граф результатів у HTML |
| `check_speech_video.py` | перевірка відео з мовленням |
| `pty_tui_check.py` | запуск TUI в псевдотерміналі з емулятором і знімок екрана |

**Останні результати** (на поточному індексі):
- набір з 80 запитів: точні фрази Hit@5 0,97, MRR@10 0,96; запити без відповіді без збігів за словами у 100 %;
  описові — Hit@5 100 %;
- еталонні вектори: всі 30 відтворюються (косинус 1,0000);
- квантизація: Q4_K_M — найгірший косинус 0,9885 (запасний варіант), Q8_0 — 0,9989, F16 — 0,9998.

Цифри чесно обмежені: набори малі, розмітка автоматична (точні фрази мають джерело за побудовою, але людина їх не
перевіряла). Переносити їх на інший корпус не можна.

## Обмеження

- Два файли `rlogo.png` у документації radare2 не є справжніми PNG і позначаються як помилка.
- Тексти більше 5 МБ пропускаються.
- Вектори всіх фрагментів тримаються в пам'яті: близько 1 ГБ на 360 тисяч фрагментів.
- Перший запит після запуску інтерфейсу триває 12–36 секунд (завантаження моделі).
- Відео зі звуком у `Projects` немає; відео перевірено на файлах поза `Projects` і на змуксованому записі мовлення.
- llama-server (GGUF) працює лише з текстом; зображення й аудіо потребують повної моделі.
- Q4-квантизація має помітну втрату точності, тому вона лише запасний варіант.
- Перевірка в терміналах інших користувачів і на інших шрифтах не виконувалась; рамки Textual залежать від шрифту.
- Розпізнавання мовлення в архіві немає: текст береться лише з готових розшифровок.

## Залежності

Список у `pyproject.toml`. Основні: Python 3.12+, `numpy`, `torch` (бажано з CUDA), `sentence-transformers`,
`pymorphy3` зі словниками `uk` і `ru`, `textual`, `rich`, `mcp<2`, `av` (PyAV: відео і m4a), `openpyxl`,
`python-docx`, `python-pptx`, `Pillow`, `soundfile`.

Системні програми (за наявності):
- `pdftotext`, `pdftoppm`, `pdfinfo` (poppler) — PDF;
- `soffice` (LibreOffice) — старі формати документів;
- `mpv` або `gst-play-1.0` — відкриття аудіо і відео з секунди;
- `evince`, `code`, `xdg-open` — відкриття PDF, коду і файлів.
